【审计维度——逐项核查，全部给出证据】

1. 需求与契约符合度
   - 每个接口的方法/路径/请求响应字段是否与开发文档 01 一致；缺字段、多字段、类型不一致；
   - 工单状态机（open→processing→closed）是否在代码中强约束，非法流转（closed 后 reply/claim、重复 close）是否被拦截；
   - 事件类型与 payload 是否与文档一致，先落库后发事件；
   - 前端路由/页面/组件是否与开发文档 02 一致，角色跳转是否齐全。

2. 安全审计（优先级最高）
   - 行级权限：user 是否只能访问自己的会话/工单；agent 是否只能访问待处理或自己负责的工单；**逐个检查所有按 ID 查询的接口**（会话详情、工单详情、评价、已读游标、事件订阅），看是否都做了归属校验；
   - 字段脱敏：用户端响应与 SSE 事件是否泄漏 intent/cited_chunk_ids/trace/escalation_count/user 内部字段；
   - 认证：JWT 过期/刷新、token_version 失效、注册/改密/登录锁定/限流是否生效；注册验证码是否可绕过；
   - 认领并发：是否用原子条件更新，两个客服同时认领是否只有一个成功；
   - 注入与泄露：日志/异常响应是否可能输出密码、API Key、token、堆栈；.env 是否被 gitignore，密钥是否出现在仓库或响应中；CORS 白名单；
   - 越权横向测试：构造“用户 A 的 token 访问用户 B 的会话/工单/事件”用例，验证返回 403 而不是数据。

3. 后端质量
   - 错误处理：异常是否被统一转成规范错误码；LLM/Embedding 故障降级路径是否兜底且不暴露内部错误；
   - 事务与并发：重复评价（唯一约束）、重复认领、重复回复、并发创建会话是否安全；
   - 事件流：event_id 幂等、scope 过滤、心跳、断线补偿；多实例部署时是否真的能切 Redis pub/sub；
   - 数据一致性：消息/工单/游标在用户端与客服端的可见性是否一致；转人工后继续留言是否仍入库且 AI 不回复；
   - 数据库：迁移是否可重复执行、索引是否覆盖常用查询（tickets.status、tickets.assignee_id、session_reads 唯一键、ticket_ratings.ticket_id）、是否存在 N+1 查询、列表分页是否走 count+limit；
   - 未读计数实现是否正确（游标口径、跨端互不干扰）。

4. 前端质量
   - 路由守卫：直接输入 URL 能否越权进入 /user/*、/workbench、/tickets-overview；
   - token 隔离：用户端与管理端 localStorage key、axios 实例是否彻底分离，退出/改密后是否清理；
   - SSE 客户端：断线重连、event_id 去重、组件卸载断开（内存泄漏）、心跳处理；
   - 状态一致性：列表与详情同步、未读红点、转人工状态条、流式渲染边界（streaming 中重复发送/快速切会话）；
   - 体验：加载/空/错误三态、表单校验与后端一致、409 认领冲突提示、输入限制；
   - 构建与代码质量：tsc/eslint 是否通过、有无明显死代码/重复代码/硬编码。

5. 性能与扩展性
   - 检索链路：embedding 调用是否每次请求都打 API（是否可缓存）、LLM 流式是否受并发限制；
   - SSE：单实例连接数上限、断线风暴、是否需要心跳/网关层；
   - 数据量增长：工单列表、会话列表、未读计数在万级/十万级数据下的查询计划是否可用；
   - 多实例/水平扩展：事件总线、会话亲和、限流（Redis）是否已为多实例准备。

6. 测试覆盖
   - 对照开发文档 03 的测试矩阵：并发认领、越权、事件过滤、脱敏、转人工闭环、注册防刷是否都有自动化用例；
   - 运行后端 pytest 全量、前端 npx tsc --noEmit，记录结果与失败项；
   - 检查测试是否只是“能跑”还是真的断言了关键行为（如抢单只有一个成功）。

【举一反三——必须做，不能只列表面问题】
1. 模式推广：从已发现的单个问题出发，检查同模式是否出现在其它接口/页面（例：会话详情有越权 → 检查工单详情/评价/事件订阅；一个接口漏脱敏 → 全量搜索所有 user 端响应模型）；
2. 系统性风险：从当前实现推断未来规模下会先爆的点（用户量、工单量、SSE 连接数、embedding 调用量），给出具体阈值与应对方案；
3. 可优化清单：不限于修 bug，包括架构、性能、安全、体验、可维护性、可观测性（日志/指标/告警）、CI/CD、文档同步，每条给出：位置、现状、问题/收益、建议方案、优先级（P0/P1/P2）、实施成本与风险；
4. 对未来功能的铺垫：结合现有数据模型判断“满意度报表、工单超时提醒、分配策略、小程序端、多租户”等后续需求是否容易落地，若有阻碍请指出。
