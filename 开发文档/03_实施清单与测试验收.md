## 5. 测试矩阵

| 场景 | 用例 | 级别 |
|---|---|---|
| 注册 | 用户名重复/密码弱/验证码错/限流 | 后端单测 + 前端表单 |
| 登录 | user 角色登录成功；失败锁定 | 后端单测 |
| 越权 | user A 访问 user B 会话/工单/事件 | 后端单测（必须 403） |
| 认领并发 | 双客服同时 claim，仅一个成功 | 后端并发测试 |
| 转人工闭环 | 转人工→created 事件→认领→回复→用户端收到→关闭→评价 | 集成测试 |
| 实时性 | SSE 断线重连后列表/未读一致 | 前端联调 + 事件去重单测 |
| 脱敏 | 用户端响应不含 intent/cited_chunk_ids/trace | 后端单测 |
| 回归 | 现有管理端 chat/知识库/评测/设置 | 全量 pytest |

## 6. 联调与验收步骤

1. 启动后端（uvicorn，127.0.0.1:8000）与前端（vite，5173）；
2. 管理端：admin 创建 1 个 agent、1 个 user 账号（或用户自助注册）；
3. 配置渠道 `web_user` 默认知识库（指向「手动测试1」）；
4. 用户端注册登录 → 提问知识库问题（应命中）→ 问胡话（应 LLM 自然回复）→ 投诉（应转人工）；
5. 客服端看到新工单 → 认领 → 回复 → 用户端实时收到 → 关闭 → 用户评价；
6. 管理端看板数字与工单状态一致；
7. 双浏览器并发验证认领冲突提示；
8. 断网重连验证事件补偿（列表全量重拉）；
9. 全量回归：`pytest`（后端）、`npx tsc --noEmit`（前端）。

## 7. 风险与回退

| 风险 | 应对 |
|---|---|
| SSE 事件泄漏 | 服务端 scope 过滤 + 专项测试；先灰度 agent 内部测试 |
| 认领并发脏数据 | 原子条件更新 + 测试覆盖 |
| 用户端流量突增 | 注册限流/登录锁定/会话数限制/chat 限流；监控指标 |
| 与现有功能回归 | 不改动现有接口权限；用户端接口独立路由；全量回归 |
| 密码/令牌安全 | bcrypt + token_version + 用户端独立 token key |
