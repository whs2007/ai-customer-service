# 开发文档 02：前端页面与组件设计

> 技术栈：React 18 + Vite + TypeScript + Ant Design + TanStack Query + Zustand
> 与现有管理端同一仓库（`frontend/`），新增路由组与布局，不改动现有管理端页面结构。

## 1. 路由规划

在 `frontend/src/router/index.tsx` 增加（现有路由保持不变）：

| 路径 | 页面 | 布局 | 角色 |
|---|---|---|---|
| /user/login | UserLogin | 独立 | 公开 |
| /user/register | UserRegister | 独立 | 公开 |
| /user/chat | UserChatPage | UserLayout | user |
| /user/tickets | UserTicketsPage | UserLayout | user |
| /user/tickets/:id | UserTicketDetailPage | UserLayout | user |
| /user/profile | UserProfilePage | UserLayout | user |
| /workbench | WorkbenchPage | WorkbenchLayout | agent/admin |
| /tickets-overview | TicketsOverviewPage | AppLayout | admin |

登录跳转（`Login` 页改造或新增公共 `redirectByRole(role)`）：

- user → /user/chat
- agent → /workbench
- admin → /dashboard

新增 `RoleGuard` 组件（类似现有 `RequireAuth`）：校验 `role` 与路由要求匹配，不匹配跳对应首页。

## 2. 令牌隔离与请求封装

现有 `frontend/src/api/token.ts` 使用 `ai_cs_access_token`。用户端必须独立：

```ts
const USER_ACCESS_KEY = 'ai_cs_user_access_token';
const USER_REFRESH_KEY = 'ai_cs_user_refresh_token';
```

- 新增 `api/userClient.ts`：基于现有 `client.ts` 逻辑复制一份，读取/写入用户端 key；
- 用户端全部请求走 `userClient`；工作台/管理端走现有 `client`；
- 用户端登录页调用 `userClient` 的登录/注册接口，保存到用户 key；
- 刷新 token 拦截器同样复制一份（避免混用）。

## 4. 页面与组件清单

### 4.1 UserLogin / UserRegister

- 居中卡片布局；登录：账号/密码/记住我/登录按钮 + “注册账号”链接；
- 注册：用户名/密码/确认密码/昵称（可选）+ 算术验证码；
- 表单校验规则与后端一致（用户名 4~32、密码 8~64 含字母数字）；
- 成功后按 role 跳转，失败提示后端 message。

### 4.2 UserChatPage（核心）

数据流：

```text
进入页面 → GET /api/user/sessions（最近会话）
  有 active 会话 → 载入会话消息
  无 → 显示空态引导
新建会话 → POST /api/user/chat {session_id: null, message}
发送消息 → 同上 SSE 流式渲染
SSE 事件：message_start / token / citations / done / error
```

组件拆分：

- `ChatConversation`：渲染消息列表（role 区分气泡样式：user 右蓝、assistant 左灰、agent 左绿带“人工”标签、system 居中灰字），自动滚动到底；
- `CitationFold`：AI 消息下的“来源：文档名”折叠；
- `TransferredBanner`：转人工状态条（复用现有文案）；
- `SessionList`：左侧最近会话（active 置顶，显示摘要与时间）；
- 发送防抖：Enter 发送、streaming 中禁用、长度 ≤ 500。

### 4.3 UserTicketsPage / UserTicketDetailPage

- 列表：状态筛选 Tabs + 表格/卡片列表；SSE（scope=user）驱动刷新（ticket.updated / ticket.closed / message.new）；
- 详情：对话流（复用 ChatConversation，只读）+ 工单状态 Timeline + 评价区（RatingModal）；
- 已关闭且未评价时显示“评价本次服务”按钮。

### 4.4 UserProfilePage

- 信息展示（username/display_name/role/created_at/last_login_at）；
- 修改昵称、修改密码（旧+新+确认）表单；
- 退出登录（清用户 token → /user/login）。

### 4.5 WorkbenchPage

数据流：

```text
进入 → GET /api/agent/tickets?status=open（默认待处理）
SSE scope=agent：
  ticket.created → 插入队列 + 未读红点
  message.new → 当前打开工单追加消息；其它工单未读+1
  ticket.claimed / ticket.closed / ticket.updated → 列表更新
点开工单 → GET /api/agent/tickets/{id} → 中栏对话 + 右栏信息 → POST read 游标
认领 → POST claim → 成功刷新
回复 → POST reply → 追加气泡
关闭 → Modal 必填原因 → POST close
```

组件拆分：

- `TicketQueue`（左）：筛选状态、列表项（未读红点、优先级色标）、认领按钮；
- `WorkbenchConversation`（中）：复用 ChatConversation + 输入框（Enter 发送）；
- `TicketInfoPanel`（右）：工单字段、用户资料、状态操作（认领/关闭）、满意度；
- `ClaimButton`：点击后处理 40900（“已被其他客服认领”提示并刷新队列）。

### 4.6 TicketsOverviewPage（admin）

- 统计卡片（total/open/processing/closed_today）；
- 超时未认领列表（stale_open）+ 手动刷新；
- SSE scope=admin 驱动刷新。

### 4.7 管理端扩展

- `AccessTab`：角色下拉加 `user`（标签“用户”）；
- `SettingsPage`：新增“渠道配置”Tab（ChannelConfigTab）：渠道 key 只读、默认知识库多选、允许转人工开关、保存。

## 5. SSE 客户端封装

新增 `frontend/src/utils/eventStream.ts`：

```ts
export function connectEventStream(
  url: string,
  handlers: Record<string, (data: unknown) => void>,
  opts?: { onOpen?; onError?; heartbeatMs?: number },
): () => void;  // 返回断开函数
```

- 内部 `EventSource` + 自动重连（浏览器原生）+ `event_id` 去重（Map 缓存最近 500 个）；
- 心跳注释行自动忽略；
- 组件卸载时断开；
- 断线重连后触发 `onReconnect` 回调（页面执行全量重拉）。

## 6. 状态管理

- 服务端状态：TanStack Query（`useQuery` / `useMutation`），key 规划：
  - `['user-sessions']`、`['user-session', id]`
  - `['user-tickets']`、`['user-ticket', id]`
  - `['agent-tickets', status, mine]`、`['agent-ticket', id]`
  - `['overview']`、`['channel-config']`
- 客户端瞬时状态：组件内 useState；用户信息复用现有 auth store（但用户端 token 独立存储）；
- 未读：由列表接口返回 `unread_count`，SSE 事件本地 +1，打开会话后清零并调用 read 接口。

## 7. 异常与空态

- 每个页面提供 loading / empty / error 三态；
- SSE 断开显示顶部细条提示“连接已断开，正在重连…”；
- 40900 认领冲突：message 提示 + 自动刷新队列；
- 403 越权：统一跳回对应首页并提示；
- 服务端 5xx：显示“服务繁忙，请稍后重试”。

## 8. 样式约定

- 用户端：白底、主色（沿用现有主题 token）、卡片圆角 12、移动优先的简洁风格；
- 工作台：信息密集但分区清晰，三栏固定高度，聊天区背景浅灰；
- 复用现有 `theme` 配置，不引入新 UI 库。
