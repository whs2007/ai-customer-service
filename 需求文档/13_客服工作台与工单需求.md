# 13 客服工作台与工单需求

> 配套文档：`11_用户端与客服工作台设计方案.md`、`12_用户端功能需求.md`
> 开发文档：`../开发文档/01_后端接口与数据模型设计.md`、`../开发文档/02_前端页面与组件设计.md`

## 1. 工单生命周期

```text
open（待处理） --认领--> processing（处理中） --关闭--> closed（已关闭）
```

| 状态 | 说明 | 谁可操作 |
|---|---|---|
| open | 用户转人工/投诉后自动创建 | 任何 agent 可认领；admin 可看 |
| processing | 已被某客服认领 | 仅 assignee / admin 可回复、关闭 |
| closed | 已关闭 | assignee / admin；关闭后用户可评价 |

规则：

- 认领采用原子条件更新（`WHERE status='open'`），同时写入 `assignee_id/claimed_at`，失败返回“已被其他客服认领”；
- 工单优先级：投诉=高、转人工=中、其他=中（沿用现有 `priority_rules` 配置）；
- 关闭必须填写原因（已解决/用户放弃/重复工单/其他）；
- 一期不做：转派、备注、快捷回复、自动分配、超时自动流转（预留字段与事件类型）。

## 2. 客服工作台

### 2.1 入口与权限

- 路径 `/workbench`；仅 `agent`、`admin` 可访问；
- `agent` 登录后默认跳转 `/workbench`；
- 工作台不显示任何系统设置/知识库/评测入口。

### 2.2 页面布局

```text
顶部：队列筛选（全部 | 待处理 | 处理中 | 我负责的）+ 在线/离线开关 + 用户信息▾

左栏：工单列表（工单号、用户昵称、摘要、未读红点、优先级色标、时间）
中栏：对话流（用户 / AI / 人工 / 系统），AI 消息可展开引用（内部字段可见）
右栏：工单信息
  - 工单号/状态/优先级/创建时间/认领时间
  - 用户信息（用户名、昵称）
  - 操作区：未认领→[认领]；已认领→[关闭工单]（必填原因）
  - 满意度（如已评价）
```

### 2.3 交互细节

- 新工单到达时左栏顶部插入并红点提醒（SSE `ticket.created`）；
- 认领成功：工单进入“我负责的”，状态变处理中，用户端同步看到状态变化；
- 回复：中栏输入框发送，Enter 发送；回复实时推送给用户端（SSE `message.new`）；
- 关闭：弹出确认框必填原因；关闭后工单从“待处理/处理中”消失，可在“全部/已关闭”筛选查看；
- 在线/离线：离线时用户端提示“当前人工客服不在线”（如已配置营业时间则按配置展示）；
- 未读：以 `session_reads` 游标计算，中栏打开会话即标记已读；
- 刷新策略：SSE 事件驱动增量刷新；断线重连后全量重拉当前筛选列表。

## 3. 管理端扩展

### 3.1 用户管理

- 现有「账号权限」Tab 角色下拉增加 `user`（标签“用户”）；
- admin 可创建 user / agent 账号、编辑角色、禁用/启用、重置密码（现有能力，仅补角色选项）；
- 列表增加“最后登录时间”列（可选）。

### 3.2 工单看板（admin）

- 新增 `/tickets-overview` 页面（或并入现有仪表盘）；
- 卡片：待处理数、处理中数、今日关闭数、总工单数、认领超时（>30 分钟未认领）提醒列表；
- 数据来自 `GET /api/admin/tickets/overview`，SSE 事件驱动刷新。

### 3.3 渠道配置

- 「系统设置」新增「渠道配置」Tab；
- 配置项：渠道 key（`web_user`）、默认知识库（多选）、是否允许转人工、营业时间（可选）；
- 保存后用户端新会话立即生效。

## 4. 实时通知需求

| 事件 | 触发 | 接收方 |
|---|---|---|
| ticket.created | 用户转人工建单 | 客服端队列、管理端看板 |
| ticket.claimed | 客服认领 | 用户端（工单状态变化）、管理端 |
| message.new | 用户/AI/人工发消息 | 会话相关方（用户端 + assignee） |
| ticket.closed | 关闭工单 | 用户端、管理端 |
| ticket.updated | 优先级/状态变更 | 相关方 |

推送要求：

- 服务端按 scope（user/agent/admin）过滤，严禁跨用户泄漏；
- 事件带 `event_id`，前端去重；断线重连后前端全量重拉列表作为兜底；
- 心跳：SSE 每 20s 发送 `: ping`；
- 多实例部署时事件走 Redis pub/sub（一期可进程内，预留接口）。

## 5. 验收标准

1. 两个客服同时认领同一工单，仅一个成功；
2. 用户转人工 → 客服端 1s 内出现工单 → 认领 → 回复 → 用户端 1s 内收到；
3. 用户端只能收到自己的工单/消息事件；
4. 关闭工单必须填原因，关闭后用户端状态正确、可评价；
5. agent 登录只能进入工作台，无法访问系统设置；
6. 管理端看板数据与工单实际状态一致。

## 6. 变更记录（实施后追加）

- 【新增】工单释放能力：assignee/admin 可将处理中工单释放回待处理（`POST /api/agent/tickets/{id}/release`），用于误认领/转派前置；释放后任何客服可重新认领。
- 【变更】职责分离（默认硬隔离）：admin 对工单只读（认领/回复/关闭/释放仅 agent）；`ALLOW_ADMIN_TICKET_OPS=true` 可临时开放并写审计。管理端工单页改只读 + "前往客服工作台处理"。
- 【变更】客服队列列表与详情权限对齐：非 admin 仅见 open 全部 + 自己负责的 processing/closed（避免"列表可见但详情 403"）。
- 【新增】工单写操作审计留痕（ticket_claim/reply/close/release）。
- 【变更】旧管理端流转（start/close）与工作台认领/关闭字段事件对齐：start 写 claimed_at、close 写 closed_at/close_reason，并补发对应 SSE 事件。
